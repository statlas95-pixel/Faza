# Развитие «Фазы»: содержание, дизайн и устойчивость

18 ноября 2026. Основание: обратная связь владельца о чрезмерно сложной стартовой диагностике, текущая карта знаний и код проекта. Это предложения и критерии проверки, а не результаты исследования всех целевых аудиторий. Требования к опыту специалиста и сложность вопросов нужно калибровать на людях.

## Что сделано в текущем этапе

- Три варианта диагностики: выпускник химического вуза, начинающий специалист, опытный специалист. Основная часть — 10/8/12 вопросов; у опытного варианта до двух уточнений. Во всех есть теория и практика по четырём областям. Вариант не присваивает уровень, а диагностическая оценка остаётся предварительной.
- Разбор по областям и ссылки на теорию после завершения; пропуски, «Не знаю», прерывание и продолжение. Прежняя начатая диагностика сохраняется отдельным банком.
- Две темы и две практики из плана: растворение/массообмен и деаэрация/вакуумирование. Синтетические данные и пределы моделей обозначены явно.
- Сброс диагностики отделён от прогресса занятий; старая копия другого устройства не возвращает сброшенные ответы. Импорт учитывает новые ответы, включая пропуски.

## Два способа реверс-промптинга

### 1. От хорошего результата — назад к требованиям

Сначала определить наблюдаемое действие ученика, затем восстановить минимальную теорию, задачу и обратную связь, которые к нему приводят. Для дизайна — разобрать успешный пользовательский путь и вывести требования к экрану. Для кода — вывести инварианты из ожидаемого поведения и закрепить их проверками.

Пример на деаэрации:

| Наблюдаемый результат | Что должно быть в платформе | Проверка |
|---|---|---|
| Ученик отличает разрежение от абсолютного давления | Определение шкал и задача 100 + (−80) = 20 кПа | Ответ и единицы; изменение атмосферного давления в задаче переноса |
| Не обещает мгновенное удаление всего газа | Различие равновесия и скорости переноса | Выбор вывода, который действительно поддерживает закон Генри |
| Не смешивает модели пузырька и испарения | Явные допущения каждой формулы | Объясняет, почему PV = const не описывает испаряющуюся смесь точно |
| Учитывает риск кипения и изменения состава | Связь температуры и давления пара, без выдачи учебного числа за рабочий режим | В задаче обнаруживает риск 5 кПа для водной модели при 40 °C |

Шаблон для методиста:

```text
Ты помогаешь автору учебной платформы «Фаза».
Аудитория: [кто и какая подготовка].
После материала человек должен уметь: [наблюдаемое действие].
Контекст и ограничения: [данные задачи, оборудование, допущения].
Доступные источники: [id из реестра и проверенные фрагменты].

Разверни цель назад: действие → типичная ошибка → нужное понятие →
минимальный пример → самостоятельная задача → перенос в другие условия.
Для каждого перехода укажи критерий проверки и недостающие источники.
Раздели подтверждённое, учебное допущение и гипотезу автора.
Не придумывай DOI, нормы, результаты испытаний и характеристики сырья.
Выдай черновик для рецензии, а не готовую аттестацию специалиста.
```

Шаблон для дизайна и кода:

```text
Вот экран/сценарий и желаемое действие пользователя: [...].
Вот наблюдаемое затруднение: [...].
Сначала восстанови требования, которые сделали бы этот путь успешным.
Для каждого требования дай минимальное изменение, проверку на 320/390/1360 px
и риск для сохранённого прогресса. Используй существующие компоненты проекта.
Отделяй наблюдение от предположения; не называй внешние сайты изученными
без реально просмотренных материалов.
```

### 2. ИИ сначала уточняет задачу

Подходит перед новым занятием, изменением маршрута или серьёзным редизайном. ИИ сначала проверяет репозиторий и контекст, затем задаёт не более трёх вопросов, ответы на которые действительно меняют реализацию. Уже известное не спрашивает повторно.

```text
Помоги сформулировать улучшение «Фазы»: [идея].
Сначала изучи текущие материалы и правила проекта.
Если важной информации не хватает, задай до трёх вопросов:
1) кто решает задачу и что сейчас не получается;
2) какое наблюдаемое действие будет признаком успеха;
3) какие данные, ограничения и сроки нельзя нарушать.
Если ответ уже есть в контексте, используй его и укажи основание.
Затем предложи один минимальный проверяемый этап и критерии готовности.
Не подменяй уточнение задачи бесконечной анкетой и не меняй рабочую базу.
```

Для внутреннего авторского помощника можно объединить оба режима: уточнение цели → обратное проектирование → черновик → проверка источников и чисел → предметная рецензия → публикация. Встроенный наставник ученика должен продолжать давать намёк без раскрытия скрытого разбора; авторский помощник — отдельный процесс, не обход этого ограничения.

## Приоритетные улучшения содержания

| Приоритет | Предложение | Зачем и как проверить |
|---|---|---|
| P0 | Предметная рецензия новых вопросов и задач представителем каждой аудитории | Отметить неоднозначности и неизвестную лексику; проверить, что выпускнику не нужен цеховой опыт для теоретического вопроса. Начать с небольшой пилотной группы, не выдавать её за психометрическую валидацию. |
| P1 | Пары «понятие → разобранный пример → самостоятельная задача → перенос» | Связать физическую/коллоидную химию с технологическим решением; измерять выполнение новой задачи, а не только просмотр темы. Новые два модуля дают первый образец. |
| P1 | Матрица покрытия теории | Для каждого навыка указать физическую основу, типичную ошибку, доступную практику и источник. Следующий контент из карты: смачивание/диспергирование порошков, растворимость/солюбилизация, фильтрование. |
| P1 | «Разбор смены» с трендами | Учить сопоставлять температуру, ток привода и вакуум. Начать с одного явно синтетического журнала, затем заменить согласованным обезличенным примером; проверить, различает ли задание опыт. |
| P2 | Рецензия «не согласен с разбором» | Собирать вопрос, выбранный вариант, версию материала и аргумент; не отправлять персональный прогресс автоматически внешнему ИИ. |
| P2 | Отложенный перенос | Через время предложить новое задание, сохранив историю оценок. Правила снижения/подтверждения уровня сначала согласовать; не понижать навык только за отсутствие визитов. |

## Приоритетные улучшения дизайна

- Сохранять спокойный вход: ясно назвать аудиторию, число основных вопросов, время и доступность теории/практики. Не прятать «Не знаю» и возможность пропуска. Текущий выбор трёх вариантов реализует это частично; последовательность «цель → вариант» проверить на пилоте, прежде чем объединять экраны.
- В результате показывать конкретные опоры рекомендации и пробелы по областям; избегать рейтинга людей, сравнивающего разные варианты. «Нет данных» должно отличаться от ошибки.
- В теме сделать устойчивой структуру «зачем → механизм → пример → границы → практика». Длинные детали оставлять раскрываемыми; единицы и допущения не прятать.
- Улучшать доступность на основе реального сценария: управление клавиатурой, видимый фокус, порядок заголовков, объявления результатов скринридером, масштаб 200 %. Проверка переполнения сама по себе не является полным аудитом доступности.
- Для дальнейшего визуального реверс-анализа выбрать 2–3 конкретных референса и сравнивать успешные действия, а не копировать чужую композицию. В этом этапе внешние референсы не исследовались.

## Приоритетные улучшения кода

- Сохранить разделение контента, движков и чистой логики. Для новых расчётных сюжетов использовать `worksheet`, не добавлять отдельный движок без новой механики.
- Версионировать изменения смысла вопросов: постоянный id нельзя переиспользовать для другого вопроса. Расширение выбранного банка требует плана совместимости уже завершённых попыток.
- Продолжить проверку конфликтов прогресса: сбросы и удаления должны иметь явную семантику, а не превращаться в восстановление устаревших данных. Перезапуск диагностики уже защищён; удаление закладок/очистка прогресса при офлайн-конфликте — отдельные кандидаты для воспроизведения и тестов.
- Добавить постоянный небольшой набор браузерных регрессий для входа, выбора варианта, смены устройства и продолжения занятия. Сейчас важные сценарии выполнены отдельными Playwright-проверками; не считать их автоматически частью Vitest.
- Продолжать отделять сборку от рабочего контейнера и проверять сохранность тома при его замене. Обновлять зависимости по проверяемым изменениям, не применять принудительный массовый откат ради чистого аудита.

## Ближайший следующий этап

Пилот новых вариантов на трёх аудиториях, затем одна следующая пара «теория + практика» из карты — смачивание и диспергирование порошков. Собрать реальные затруднения и пересмотреть формулировки до добавления большого банка. Это предложение следующего этапа; новая диагностика не объявляется валидированным профессиональным экзаменом.
