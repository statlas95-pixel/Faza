# Инструкция автора

Всё, что видит ученик, лежит в папке `content/`. Файлы открываются любым текстовым редактором (удобнее VS Code).
После любой правки выполните `npm run check` — он укажет файл и суть ошибки.

## 1. Исправить формулировку в теме

Откройте `content/topics/<тема>.md`. Ниже шапки (между строками `---`) — обычный текст в Markdown.

| Что нужно | Как записать |
|---|---|
| Ссылка на термин | `[[lgn]]` или `[[lgn\|гелевой сети]]` — id из `glossary.yaml` |
| Ссылка на источник | `[@tadros2013]` или `[@a; @b]` — id из `sources.yaml`; ставьте сразу после утверждения |
| Формула | `$v = \Delta\rho g d^2 / 18\eta$` в строке, `$$ ... $$` отдельным блоком (LaTeX) |
| Углублённый блок | строка `:::deep Заголовок`, текст, строка `:::` |
| Пометка «учебная модель» | `:::model Заголовок` … `:::` |
| Переход к практике | `:::decision Заголовок` … `:::` |
| Изображение | `![описание](media:файл.svg "Подпись")` |
| Интерактив | отдельная строка `{{widget:stokes}}` (доступны: `stokes`, `flowcurve`, `passes`, `cooling`, `saltcurve`, `interaction`, `demo-destabilization`) |
| Ссылка на тему / занятие | `[текст](#/topics/id)`, `[текст](#/labs/id)` |

Шапка темы: `title`, `summary`, `domain`, `area` (`production`, `rnd`, `both`), `order`, `minutes`, `questions` (рабочие вопросы — по ним тема находится в поиске), `labs`, `related`, `review` (статус рецензии — обновляйте после проверки экспертом), `search` (готовые английские запросы для поиска внешних источников по теме), `checks`.

Проверочный вопрос:

```yaml
checks:
  - q: Текст вопроса
    options:
      - text: Вариант
        why: Пояснение, почему это не так
      - text: Верный вариант
        correct: true
        why: Пояснение
```

## 2. Добавить источник

Добавьте запись в `content/sources.yaml` (образец — любая существующая). Обязательны `supports` (какое утверждение подтверждает) и `verified` (как вы его проверили). DOI и URL указывайте только проверенные.

## 3. Заменить или добавить изображение

1. Положите файл в `content/media/`.
2. Добавьте запись в `content/media.yaml`: `file`, `title`, `author`, `source` (ссылка на страницу файла), `license`, `attribution`, `alt`.
3. Вставьте в тему: `![описание](media:файл.jpg "Подпись")`.

`npm run check` не пропустит файл без записи в реестре.

## 4. Изменить данные занятия

Откройте `content/labs/<занятие>.yaml`.

- **Расследование** (`engine: investigation`): документы, запросы, гипотезы, решения, меры и тексты разбора полностью заданы в файле.
  - ячейка, начинающаяся с `~`, показывается как рукописная;
  - `id` у строки нужен, только если на неё ссылается `needs`;
  - `needs` — список id строк/запросов: основание засчитывается, если ученик отметил хотя бы одну такую строку или получил хотя бы один такой запрос;
  - у каждой гипотезы четыре статуса (`main`, `contrib`, `excluded`, `untested`), у каждого — `verdict` (`ok`, `weak`, `wrong`), `text` и при необходимости `noBasis` (текст для случая «вывод верный, но оснований ученик не видел»);
  - `variants` у решения меняют его оценку в зависимости от данных ученика: `when: [id-запроса]` или `when: ["main:id-гипотезы"]`.
- **Стенд стабильности** (`engine: stability`): таблица вязкости, масла, способы гомогенизации, цели — в разделе `model`.
- **Перенос на реактор** (`engine: scaleup`): параметры аппаратов — в `params`.
- **Кабинет реолога** (`engine: rheo`): параметры образцов — в `samples`.
- **Солевая кривая** (`engine: salt`): кривая — `curve`, партия — `batch`, документы и вопрос — там же.
- **Десять опытов** (`engine: doe`): факторы — `factors`, модель отклика — `model`, бюджет — `budget`.

Если меняете числа в трёх последних занятиях, запустите `npm test`: тесты проверяют, что задача остаётся решаемой, а примеры в текстах сходятся с моделью. При необходимости поправьте ожидаемые значения в `tests/models.test.ts`.

## 5. Создать новое занятие по образцу

Проще всего — новое расследование:

1. Скопируйте `content/labs/batch-3108.yaml` (короткий образец) под новым именем.
2. Измените `id` (должен совпадать с именем файла без расширения — так удобнее), `title`, `order` и содержимое.
3. Удалите строку `transferOf`, если это самостоятельное занятие; чтобы привязать занятие-перенос, укажите в основном занятии `transfer: <id>`.
4. Добавьте id занятия в `labs` у связанных тем и, при желании, в `content/site.yaml`.
5. `npm run check`.

Новые типы механик требуют программирования: движок — файл в `src/labs/`, подключается в `src/labs/LabPage.tsx`.

## 5а. Карта знаний, навыки и диагностика

| Что изменить | Где |
|---|---|
| Место темы в иерархии «Раздел → Модуль → Тема», предпосылки, темы «в плане» | `content/curriculum.yaml` |
| Порядок тем для каждой цели | там же, раздел `goals` |
| Навык: название, результат обучения, какие темы и занятия его подтверждают | `content/skills.yaml` |
| Задания входной диагностики | `content/diagnostic.yaml` |
| Подсказки авторов в занятии (работают без ИИ) | поле `hints` в файле занятия |

Каждая новая тема должна быть размещена в карте и привязана к навыку — `npm run check` это проверяет. Правила расчёта уровней — в `shared/mastery.ts`; после их изменения запустите `npm test`.

**Занятие-расчёт по шагам** (`engine: worksheet`) задаётся файлом целиком: скопируйте `content/labs/mixing-sheet.yaml`, замените паспортный лист (`sheet`), шаги (`steps`) и блок переноса. У вопроса могут быть `hint` и `explain`; `after` — запись, которая появляется после верного решения шага.

## 6. Внешние источники: от кандидата до учебной базы

1. Пользователи сохраняют найденные записи в подборку и могут отметить «Предложить редактору».
2. `npm run candidates` показывает предложенные записи.
3. Редактор читает первоисточник. Только после этого запись добавляется в `content/sources.yaml` с полями `supports` и `verified`, и на неё можно ссылаться в темах.
4. Первичные документы производителей и регуляторов добавляются в `content/tech-docs.yaml` (поля `scope` и `checked` обязательны по смыслу).

ИИ-наставник получает только материалы из `content/`; внешняя запись в его контекст попадает лишь как помеченный «внешний материал».

## 7. Опубликовать

`npm run build` создаёт `dist/index.html` — один файл. Его можно открыть локально, переслать или разместить на любом статическом хостинге.
