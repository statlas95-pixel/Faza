# Контроль лимитов и передача работы

Правило проекта для Codex закреплено в `AGENTS.md`. Его цель — сохранить проверяемую работу до вынужденной остановки, а не гарантировать доступ к данным, которых платформа не предоставляет.

На 18 ноября 2026 в доступном наборе инструментов нет канала, который возвращает реальный остаток лимита ChatGPT/Codex текущего пользователя. Квоты Scite, API провайдеров и дневной лимит наставника платформы — другие величины. Их нельзя выдавать за лимит пользователя ChatGPT. Резерв 20/10 % применяется только если платформа действительно предоставляет счётчик или предупреждение.

При недоступном счётчике основной механизм — обязательная контрольная точка после каждого связанного, проверенного этапа. Не откладывать сохранение до конца длинной сессии. Незавершённый этап остаётся в рабочей ветке с явным статусом; сломанный код не публикуется ради формального коммита.

Шаблон `docs/SESSION_STATE.md`:

```text
Дата и задача:
Источник сведений о лимите: доступный счётчик / предупреждение / недоступен
Фактический остаток: значение с единицами и окном лимита / неизвестен
Ветка и базовый коммит:
Законченный этап:
Свежие проверки и результаты:
Осталось по запросу пользователя:
Известные риски и непроверенное:
Следующий конкретный шаг:
Публикация: локально / ветка / PR / main / подтверждённый live
```

Не помещать в записи ключи, пароли, приватные заголовки запросов или содержимое пользовательской базы. Не создавать автоматические напоминания вместо недоступного счётчика и не повторять запросы после явного исчерпания лимита. Для ограничения области этапа достаточно краткого списка результатов; фиксированный таймер не является измерением токенов.
