# Устройство «Фазы» и ориентиры для изменений

Описание существующего кода по результатам проверки 17 ноября 2026. Результаты конкретных прогонов — в `HANDOFF.md`; синтаксис материалов — в `docs/AUTHORING.md`.

## Поток данных

```text
content/ ── src/content.ts ── страницы и движки занятий
    │                              │
    │                        src/learning.ts
    │                              │
    │                     shared/mastery.ts
    │                              │
    │                         src/store.ts ── localStorage
    │                              │
    │                         src/account.ts
    │                              │ /api/me/state + baseRev
    └── server/content.ts ── server/app.ts ── SQLite
                                  │
                     shared/merge.ts, поиск, наставник
```

Интерфейс подключает материалы при сборке через `import.meta.glob`, сервер читает те же файлы для поиска и контекста наставника. Изменение контента требует новой сборки и перезапуска сервера.

## Повторяющиеся подходы

| Задача | Существующий подход |
|---|---|
| Теория, проверочные вопросы, занятие | Markdown/YAML в `content/`; предметные формулировки не переносятся в React. |
| Маршрут, связи и оценка | `curriculum.yaml`, `skills.yaml`, `diagnostic.yaml`; чистые функции `shared/mastery.ts`; связующий слой `src/learning.ts`. ИИ не выставляет оценку и не строит маршрут. |
| Занятие-расчёт | Сначала использовать `engine: worksheet`, шаги и вопросы в YAML. Новый движок нужен для новой механики, подключается в `src/labs/LabPage.tsx`. |
| Состояние занятия | `useLabState`, `LabFrame`, `Brief`, `Transfer`, `DebriefLinks`. Завершение — через `markFinished`/`finishLab`. |
| Расчётные модели | Чистые функции `src/models/physics.ts`, СИ внутри расчёта; единицы и допущения показываются в материале. |
| Изменение прогресса | `update`, `saveLab`, `addEvidence` и другие операции `src/store.ts`. Объект `getProgress()` не изменять напрямую: подписчикам `useSyncExternalStore` нужна новая ссылка. |
| API своего сервера | `api` из `src/account.ts`, обработка `ApiError`, понятное сообщение пользователю. |
| Учебная разметка и виджеты | `Md`/`MdInline`, реестр `src/widgets/index.tsx`, общие `QuestionCard` и `Quiz`. |
| Недоверенный внешний текст | `renderSafe` без HTML. `renderMd` допускает HTML и предназначен для контролируемых файлов репозитория. |
| Оформление | Переменные, карточки, кнопки, адаптивные правила в `src/styles.css`; режимы explore/focus/debrief. |

## Инварианты совместимости

- `id` темы, занятия, навыка и диагностического задания используется в URL, закладках, попытках и пользовательском прогрессе. Переименование требует миграции ссылок и данных.
- Тема карты задаётся один раз; повторное упоминание — через `also`. Граф предпосылок должен быть без циклов: `buildRoute` обходит его рекурсивно. Валидатор отклоняет циклы, битые связи и дубли id.
- Ключ гостевого прогресса — `faza.progress.v1`, пользовательского — `faza.user.<id>`. Старые записи дополняет `normalize` в `shared/merge.ts`; изменение формата сопровождается тестом со старой записью.
- Сервер получает `baseRev`, при устаревшей ревизии использует `mergeProgress`. Попытки и свидетельства объединяются по id, актуальность определяется временем. Проверять разделение пользователей и сохранность незавершённых занятий.
- Просмотр темы не повышает уровень навыка. Самостоятельный уровень требует результата занятия не ниже 80 % без подсказок. Перенос даёт уровень 4 только при самостоятельном решении. Повтор одного источника не увеличивает уверенность.
- `finishLab` записывает попытку, счётчик, свидетельства и сбрасывает подсказки. Вызывать один раз за завершение.
- `tol` числового вопроса — относительная погрешность, по умолчанию 5 % от модуля правильного ответа. Это не абсолютный допуск; нулевой ответ сейчас требует точного нуля.
- Обучение работает без аккаунта и внешних API. `HashRouter` нужен также для открытия `dist-single/index.html` через `file:`; смена роутера требует отдельной проверки этого режима.
- До завершения занятия наставник получает открытые материалы; для намёка и разбора незавершённого занятия теория исключается. Ключи ответов и скрытый разбор не добавлять в контекст.
- Авторизация — better-auth и httpOnly-cookie. Попытки доступны владельцу; изменяющие API-запросы проверяют Origin. Секреты провайдеров остаются на сервере.
- SQLite, секрет сессий и outbox находятся в папке данных, на Render — на диске `/data`. Изменения таблиц выполняются новой миграцией в `server/db.ts`. Базу и секреты не включать в Git или архив исходников.

## Проверка изменений

Node.js 24: `npm ci`, `npm run check`, `npm test`, `npm run build`. При изменении загрузки, путей, роутера и зависимостей — также `npm run build:single`. Эти команды выполняет GitHub Actions для PR и `main`. Наличие workflow не делает проверки обязательными в настройках защиты ветки.

В браузере проверять изменённый сценарий, сохранение после перезагрузки и ширины 320, 390, 1360 px. Исправлять источник переполнения, не скрывать его на `body`. Широкие таблицы прокручиваются внутри контейнеров. Переход к термину должен сбрасывать скрывающие его фильтры и показывать подсвеченную запись.

Для прогресса: гость, импорт, выход/повторный вход, старая запись и начатое занятие. Использовать отдельную тестовую базу. Проверка подставных провайдеров в тестах не означает проверку живого ИИ или поискового API.

Согласно конфигурации, описанной в `HANDOFF.md`, Render автоматически публикует `main`. Слияние может запустить развёртывание; успешное слияние не подтверждает запуск сайта.

## Открытые вопросы

- `npm audit --omit=dev` на 17 ноября 2026: две записи moderate в цепочке `react-router`/`react-router-dom` 6.30.6. [GHSA-wrjc-x8rr-h8h6](https://github.com/advisories/GHSA-wrjc-x8rr-h8h6) — перенаправление через обратную косую черту; [GHSA-337j-9hxr-rhxg](https://github.com/advisories/GHSA-337j-9hxr-rhxg) — SSR-гидратация. SSR в проекте нет; это не устраняет результат аудита. Предлагаемое исправление — 7.18.5, отдельная миграция с проверкой маршрутов, импортированных путей и режима `file:`. Не подменять проверку миграции командой `npm audit fix --force`.
- Динамические импорты `account.ts` и `store.ts` не выделяют их в отдельные чанки из-за статических импортов. Это предупреждения сборки, не ошибки выполнения.
- У восьми источников не подтверждены DOI/URL. Не придумывать ссылки ради чистого отчёта; предметная рецензия описана в `HANDOFF.md`.
