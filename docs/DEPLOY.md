# Размещение и конфигурация

## Что запускается

Один процесс Node.js: в Docker — `node dist-server/index.js`, локально в разработке — `server/index.ts` через tsx. Он отдаёт интерфейс из `dist/`, API `/api/*`, хранит данные в SQLite-файле.
Отдельный сервер базы данных не нужен.

`npm run build` проверяет типы и собирает интерфейс и сервер; `npm start` затем запускает тот же JS-сервер, что и Docker. Docker использует отдельные этапы: инструменты при сборке и `npm ci --omit=dev --omit=optional` в рабочем образе. Там нет Vite, Vitest, tsx, esbuild и picomatch. Результаты аудита и ограничения — в `docs/SECURITY.md`.

| Что | Где | Комментарий |
|---|---|---|
| База | `<FAZA_DATA_DIR>/faza.db` | аккаунты, сессии, прогресс, попытки, кэш поиска. Делайте резервную копию файла |
| Секрет сессий | `FAZA_AUTH_SECRET` или `<данные>/auth-secret` | создаётся при первом запуске; при смене секрета все сессии сбрасываются |
| Письма сброса пароля | SMTP (`SMTP_URL`) или `<данные>/outbox/*.txt` | без SMTP письмо читает тот, кто имеет доступ к серверу |
| Ключи ИИ | `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` | только в окружении сервера |

Все переменные — в `.env.example`.

## Локально (Windows)

`start.bat` или `npm install`, затем `npm start` → http://localhost:8787. Требуется Node.js 22.13+ (LTS 22 или 24).
В корпоративной сети с прокси добавьте в окружение `NODE_USE_ENV_PROXY=1` и `HTTPS_PROXY=...`
(при собственном корневом сертификате — `NODE_EXTRA_CA_CERTS=путь\к\ca.pem`), иначе внешний поиск и ИИ не выйдут в сеть.

Доступ коллег в локальной сети: запустите с `FAZA_BASE_URL=http://<имя-или-IP-компьютера>:8787` и откройте порт 8787 в брандмауэре Windows.
По обычному http cookie работает; для доступа из интернета нужен https.

## Онлайн

Подойдёт любой хостинг, который запускает контейнер или Node-процесс и даёт **постоянный диск**:

```bash
docker build -t faza .
```

```bash
docker run -d -p 8787:8787 -v faza-data:/data -e FAZA_BASE_URL=https://faza.example.org --env-file .env faza
```

Обязательно:

1. `FAZA_BASE_URL` — публичный https-адрес. От него зависят cookie (флаг Secure), проверка источника запросов и ссылки в письмах сброса пароля (адрес возврата: `<FAZA_BASE_URL>/#/account?reset=…`).
2. Постоянный том для `/data`. На платформах без диска данные пропадут при перезапуске.
3. `SMTP_URL` и `SMTP_FROM` — иначе пользователи не смогут сами восстановить пароль.
4. https обеспечивает хостинг или обратный прокси (Caddy, nginx). Если перед сервером стоит прокси, пробросьте заголовок `Origin` без изменений.

Проверка собранного образа без обращения к рабочей базе:

```bash
docker build --tag faza:runtime-check .
npm run check:runtime
```

Нужны Docker и Node.js 24 на машине проверки. Скрипт создаёт тестовые контейнеры и том, проверяет интерфейс, API, авторизацию и сохранность данных после замены контейнера, затем удаляет только свои ресурсы.

Образ собран и проверен локально и в GitHub Actions. Для локального прокси использовался временный BuildKit-секрет с CA в отдельной копии Dockerfile; сертификат не добавлялся в репозиторий и слои образа. 18 ноября 2026 коммит `627fd67` успешно опубликован на существующем сервисе Render: https://faza-1boj.onrender.com. Проверены HTTP/API и гостевые сценарии на публичном сайте; подробности — в `HANDOFF.md`.

Если в настройках Render задано переопределение Docker-команды, используйте `node dist-server/index.js` либо уберите переопределение для применения `CMD` образа. Старый запуск `npx tsx server/index.ts` для нового образа не подходит. Путь диска `/data`, формат базы и секрет сессий сохранены.

## Обновление версии

Остановить процесс → сделать копию `faza.db` → обновить код → `npm install` → `npm start`.
Миграции собственных таблиц (`server/db.ts`) и таблиц авторизации применяются при старте автоматически и повторно не выполняются.
Прогресс, сохранённый версией 0.1 в браузере, читается версией 0.2 без преобразований и предлагается к импорту в аккаунт после входа.

## Свой домен

1. Купите домен у регистратора (для аудитории в РФ удобны зоны `.ru` / `.рф`; подойдёт любая).
2. В Render: сервис Faza → Settings → Custom Domains → добавить домен; Render покажет DNS-записи (CNAME или A), которые нужно внести у регистратора. Сертификат https Render выпустит сам.
3. В переменных окружения сервиса задать `FAZA_BASE_URL=https://<ваш домен>` и, на время переезда, `FAZA_TRUSTED_ORIGINS=https://faza-1boj.onrender.com`.
4. Когда новый адрес проверен — добавить `FAZA_CANONICAL_REDIRECT=1`: запросы на прежний адрес будут перенаправляться на новый.

Важно: cookie входа привязана к адресу. После смены адреса пользователям нужно один раз войти заново; аккаунты и прогресс на сервере сохраняются.
Ссылки в письмах восстановления пароля строятся от `FAZA_BASE_URL`.

## Доступность из России без VPN

Что сделано в приложении (версия 0.3): браузер не обращается ни к каким сторонним адресам (шрифты и библиотеки раздаёт сам сервер);
первый экран — около 0,4 МБ со сжатием вместо 3,6 МБ, файлы кэшируются. Это помогает на медленных и ограниченных каналах, но не снимает блокировку, если она на уровне сети.

Что **не проверено**: доступность `onrender.com` и адресов Render от российских провайдеров — из среды разработки это проверить нельзя. Сначала выясните, что именно происходит без VPN:
сайт не открывается совсем, открывается частично или очень медленно — и у всех ли провайдеров (домашний интернет, мобильная сеть).

Варианты, от простого к надёжному:

| Вариант | Что нужно | Ограничение |
|---|---|---|
| Свой домен на Render | шаги из раздела выше | поможет, только если блокируется именно имя `onrender.com`, а не сеть Render |
| Перенос на хостинг, доступный из РФ | VPS или облако с Docker; тот же `Dockerfile`; том для `/data`; перенос файла `faza.db` | провайдер ИИ (Cerebras) может не принимать запросы с российских адресов — тогда наставник будет недоступен, обучение продолжит работать |
| Прокси в РФ перед Render | небольшой сервер с Caddy или nginx, проксирующий на Render | нужно проверить, что связь сервер–Render из РФ не ограничена |

Перенос данных: остановить сервис, скопировать `faza.db` (и `auth-secret`, чтобы не сбросить сессии) с диска Render на новый сервер, запустить контейнер с тем же `FAZA_BASE_URL`.
