## Оставшаяся уязвимость

[GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf): ReDoS в `picomatch` при специально составленных повторяющихся extglob-шаблонах. Установлена версия 4.0.7; advisory указывает диапазон `<=4.0.7`, исправленная версия не указана. Последняя опубликованная версия в доступном npm-реестре на дату проверки — 4.0.7.

Полный `npm audit` сообщает о **7 записях high**, связанных с этой одной уязвимостью: `picomatch`, `fdir`, `tinyglobby`, `vite`, `vitest`, `@vitejs/plugin-react`, `vite-plugin-singlefile`.

`npm audit --omit=dev` сообщает о **5 записях high** в той же цепочке. Причина включения инструментов в этот отчёт — необязательный peer `vitest` у серверной зависимости `better-auth`; при пересоздании lock-файла npm помечает соответствующий граф как optional/devOptional. Это не новая уязвимость React Router и не чистый production-аудит.

В текущем коде шаблоны `import.meta.glob` заданы разработчиком в `src/content.ts`; пользовательские запросы не передаются в glob-движок. Уязвимость в среде разработки и сборки остаётся. Не добавлять обработку внешних glob-шаблонов без отдельной оценки.

## Ограничение риска в рабочем контейнере

Dockerfile разделён на этап сборки и рабочий этап. Сервер собирается командой `npm run build:server` в `dist-server/index.js`, зависимости остаются внешними. Рабочий этап устанавливает их через `npm ci --omit=dev --omit=optional`, копирует `dist/`, `dist-server/`, `content/` и запускает `node dist-server/index.js`. `picomatch`, Vite, Vitest, tsx и esbuild физически отсутствуют в `node_modules` рабочего образа; это проверяет `npm run check:runtime`.

Внутри этого образа `npm audit --omit=dev --omit=optional` сообщает о **0 известных уязвимостей npm** на дату проверки. Флаги аудита соответствуют установке; без `--omit=optional` учитываются также необязательные пакеты из общего lock-файла. Это не исправление библиотеки в сборочном этапе и не аудит системных пакетов базового образа.

GitHub Actions собирает настоящий образ, проверяет отсутствие указанных инструментов, интерфейс и API, регистрацию, доступ только к своим попыткам, вход и сохранность данных после замены контейнера на том же тестовом томе. Затем выполняется аудит рабочего этапа с порогом moderate. Это не включает обязательные правила защиты ветки автоматически.

Предлагаемые npm откаты Vite/Vitest и плагинов затрагивают основные версии и не являются проверенным исправлением для текущего проекта. Они не применялись. `npm audit fix --force` и правка вручную флагов lock-файла ради исключения пакетов из отчёта не выполнялись.

Следующий технический шаг: отслеживать исправленную версию `picomatch` либо исправление в использующих его инструментах. После обновления повторить полный аудит, установку по lock-файлу, тесты и обе сборки. Это оставшаяся известная проблема, а не подтверждение безопасности всего проекта.
