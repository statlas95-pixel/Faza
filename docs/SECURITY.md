## Оставшаяся уязвимость

[GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf): ReDoS в `picomatch` при специально составленных повторяющихся extglob-шаблонах. Установлена версия 4.0.7; advisory указывает диапазон `<=4.0.7`, исправленная версия не указана. Последняя опубликованная версия в доступном npm-реестре на дату проверки — 4.0.7.

Полный `npm audit` сообщает о **7 записях high**, связанных с этой одной уязвимостью: `picomatch`, `fdir`, `tinyglobby`, `vite`, `vitest`, `@vitejs/plugin-react`, `vite-plugin-singlefile`.

`npm audit --omit=dev` сообщает о **5 записях high** в той же цепочке. Причина включения инструментов в этот отчёт — необязательный peer `vitest` у серверной зависимости `better-auth`; при пересоздании lock-файла npm помечает соответствующий граф как optional/devOptional. Это не новая уязвимость React Router и не чистый production-аудит.

В текущем коде шаблоны `import.meta.glob` заданы разработчиком в `src/content.ts`; пользовательские запросы не передаются в glob-движок. При этом Docker-образ устанавливает также инструменты сборки, и результат аудита нельзя игнорировать или представлять как отсутствие уязвимостей. Не добавлять обработку внешних glob-шаблонов без отдельной оценки.

Предлагаемые npm откаты Vite/Vitest и плагинов затрагивают основные версии и не являются проверенным исправлением для текущего проекта. Они не применялись. `npm audit fix --force` и правка вручную флагов lock-файла ради исключения пакетов из отчёта не выполнялись.

Следующий технический шаг: отслеживать исправленную версию `picomatch` либо исправление в использующих его инструментах. После обновления повторить полный аудит, установку по lock-файлу, тесты и обе сборки. Это оставшаяся известная проблема, а не подтверждение безопасности всего проекта.
